PROC0324  Early Payment RiskHigh
Detection Logic
Flags invoices where clearing date precedes baseline due date. Due date = invoice posting date + payment term days (LFB1.ZTERM). Triggered when clearing_date < (posting_date + term_days) AND disc_pct < 0.01%.
SAP Tables & Fields
BKPF.BUDAT • BSEG.ZFBDT
LFB1.ZTERM • REGUH.ZALDT
BSEG.ZBD1T (discount days)
Threshold
Any payment >0 days early with no discount (ZBD1P < 0.01%).
False Positive Controls
Excludes payments with active discount terms, month-end accruals, and intercompany postings.
PROC0308  Price Variance RiskHigh
Detection Logic
Compares MIRO invoice price to PO unit price (EKPO.NETPR). Flags where variance > tolerance. SoD flag: CDPOS shows PO price edited by same user who posted the invoice.
SAP Tables & Fields
EKPO.NETPR • RBKP.WRBTR
RSEG.WRBTR • CDPOS.VALUE_NEW
CDHDR.USERNAME
Threshold
Default tolerance: 10%. SoD flag at any variance where edit user = invoice user.
False Positive Controls
Excludes framework orders, estimate-based service orders. Validates GR quantity before flagging.
PROC0148  Duplicate PaymentsCritical
Detection Logic
Identifies 2+ cleared payment docs (BSTAT='A') to same vendor, same amount, matching invoice reference within configurable window. Confirms double-disbursement via REGUH bank account match.
SAP Tables & Fields
BKPF.BSTAT='A' • BSEG.LIFNR
BSEG.XBLNR • BSEG.WRBTR
REGUH.BANKI • REGUH.ZALDT
Matching Logic
Exact: vendor + amount + ref. Fuzzy: same vendor + amount + ref within edit distance 2 (catches slash vs dash).
False Positive Controls
Excludes recurring agreements (AUTYP='D'). Validates no credit memo between payments. Requires REGUH bank confirmation on both docs.
PROC0144  Invoice Exceeds POHigh
Detection Logic
Cumulative invoiced amount against a PO line exceeds the approved PO net value. Flags where SUM(invoice line amounts) > EKPO.NETWR for same PO and line item.
SAP Tables & Fields
EKPO.NETWR (PO net value)
RSEG.WRBTR (invoice line amt)
BKPF.BUKRS (company code)
RSEG.EBELP (PO line item)
Threshold
Flagged when cumulative invoiced amount exceeds PO value. Impact = excess above PO value.
False Positive Controls
Excludes reversals (BSTAT='Z'). Excludes framework orders where over-delivery is permitted. Validates against GR quantity.
PROC0162  Vendor Advance RiskCritical
Detection Logic
Identifies advance payments (special GL indicator 'A') posted via FB60/FV60 with no PO reference, or advances outstanding beyond threshold days without GR/settlement. Also flags advances where vendor was created within 90 days of advance posting.
SAP Tables & Fields
BSEG.UMSKS (special GL ind.)
BSEG.EBELN (PO reference)
BKPF.BLDAT (posting date)
LFA1.ERDAT (vendor creation)
BSEG.DMBTR (amount)
Threshold
Outstanding >90 days without settlement = flagged. Amount > INR 1,000,000 with no PO = Critical.
False Positive Controls
Excludes advances with active PO and GR confirmation. Excludes recurring advance agreements with documented approval. Validates vendor creation date vs advance date.

🔒 Case Registration & Chain of Custody
Case Creation
Cases created on import. ID format: APX-[LK|RC]-YYYY-NNNN. Unique, non-reusable, timestamped.
Modification Controls
TRAE evidence is read-only after registration. Only workflow fields may be modified. All changes are timestamped with user identity.
Action Logging
Every action is logged with: type, user, timestamp, value. Log is append-only — no deletions permitted.
Document Attachments
Documents stored with filename, uploader, timestamp, and SHA-256 hash for integrity verification.
Closure Gate
Recovery cases close only after credit note received (Stage 4). Partial closures require documented reason and approving officer name.
Audit Trail Export
Full case audit trail exportable as structured PDF for external audit or regulatory submission.
⚠ Limitations & Caveats
⚠
Detection is not exhaustive
Apex covers 15 defined rules. Patterns outside these rules will not surface. Scope expands as additional rules are activated in SARA.
⚠
False positive rate: 8–15%
PROC0315 has highest rate (~18%) due to configuration-driven mismatches. All findings require human review before action is taken.
🚫
Probability scores are indicative only
Scores are from a deterministic formula, not statistical predictions. Actual outcomes depend on operational factors not captured in SAP data.
🚫
Recovery is not guaranteed
High recovery probability does not constitute legal certainty. The Evidence Pack supports a factual claim under unjust enrichment principles. Disputes require legal review.
💡
Data latency
TRAE updated daily. Intraday transactions will not appear until the next refresh.
💡
Currency
All amounts in USD at transaction posting date rate (BKPF.KURSF). Does not reflect subsequent movements.
